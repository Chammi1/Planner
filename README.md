# Sota Planner — серверная версия

Подготовлено для Ubuntu 24.04 и домена bot.sotaholder.ru. Доступ: https://bot.sotaholder.ru:8443.

## Важно до запуска

- Amnezia Xray занимает TCP/UDP 443; AWG — UDP 37923. Этот проект не публикует эти порты и не управляет контейнерами Amnezia. Не меняйте их настройки ради установки.
- Используются TCP 80 (проверка сертификата и редирект) и TCP 8443 (HTTPS). Они должны быть доступны извне, в том числе в firewall провайдера. Не включайте UFW вслепую.
- DNS A уже направлен на сервер по присланной диагностике. Проверьте также AAAA: неверная IPv6-запись мешает выпуску сертификата. При проксировании DNS-провайдером сначала используйте прямую DNS-запись и проверьте поддержку внешнего порта.
- Docker установлен, Compose v5.6.0 проверен пользователем. Установка Docker, его перезапуск и изменение firewall в скриптах отсутствуют.
- Создание новой Docker-сети всё равно добавляет сетевые правила. Архив не тестировался на вашем сервере: после запуска обязательно проверьте VPN.
- Если у бота уже есть обработчик, не запускайте второй. В проекте bot — необязательный профиль, по умолчанию НЕ запускается.

## Состав

- frontend/index.html — вся текущая функциональность: календарь, привязки, планирование, дневная статистика, метрики по делам.
- backend/ — FastAPI API, PostgreSQL-хранилище и необязательный polling-бот.
- deploy/Caddyfile — HTTPS, HTTP-01 через порт 80; TLS-ALPN отключён, чтобы не использовать занятый 443 снаружи. В контейнере HTTPS на 443, на хосте отображён в 8443. HTTP/3 отключён.
- compose.yaml — проект с отдельным именем sotaplanner, именованные тома PostgreSQL и сертификатов. База и API не публикуют портов на хосте.
- scripts/ — проверки, ручной backup/restore.
- MIGRATION.md — перенос старого localStorage.

## 1. Загрузить архив

На сервере:

```bash
mkdir -p /opt/sotaplanner
cd /opt/sotaplanner
```

Загрузите содержимое архива в эту папку через SFTP. Файл compose.yaml должен оказаться непосредственно в /opt/sotaplanner, а не ещё на один уровень глубже. Не загружайте файлы в каталоги Amnezia. Можно распаковать ZIP локально и загрузить папки через SFTP.

## 2. Настроить .env

```bash
cd /opt/sotaplanner
umask 077
cp .env.example .env
chmod 600 .env
python3 -c 'import secrets; print(secrets.token_hex(32))'
nano .env
```

Последняя Python-команда выдаёт случайный пароль: вставьте его в POSTGRES_PASSWORD (hex без специальных символов). Замените ACME_EMAIL своим email, BOT_TOKEN токеном существующего бота и OWNER_TELEGRAM_ID своим числовым ID пользователя, НЕ ID бота. Не присылайте .env в чат и не публикуйте его в Git. По умолчанию часовой пояс Asia/Yekaterinburg; он используется для «сегодня» в вебе и боте.

Не меняйте POSTGRES_PASSWORD после инициализации существующего тома без отдельного изменения пароля роли PostgreSQL: изменение .env само по себе пароль в БД не меняет. Параметры DOMAIN и PUBLIC_URL согласованы с Caddy и внешним портом; для другого домена потребуется обновить их оба и DNS.

## 3. Проверки и запуск веб-части

```bash
sh scripts/preflight.sh
docker compose build api
docker compose run --rm --no-deps api python -m unittest discover -s tests -v
docker compose up -d db api web
docker compose ps
docker compose logs --tail=80 api web
```

Тесты core не требуют соединения с БД, но нужен корректно заполненный .env, поскольку Compose проверяет его заранее. Зависимости разрешаются при сборке в указанных диапазонах; полного lock-файла с хешами пока нет. Перед обновлениями делайте backup.

Проверьте с компьютера/телефона по внешней сети:

```bash
curl --fail https://bot.sotaholder.ru:8443/api/health
```

Ожидается {"ok":true}. Сертификат выдаётся при доступном извне TCP 80 и корректных A/AAAA. Выпуск может занять некоторое время; при ошибке проверьте логи web, DNS и firewall провайдера. Не обходите проверку сертификата через curl -k как способ постоянной эксплуатации.

Проверьте также, что оба VPN продолжают работать, а их контейнеры не перезапускались:

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

Публичный GET /api/health показывает только состояние сервиса, не пользовательские данные. GET /api/state без входа должен отвечать 401.

## 4. Проверить существующего бота

```bash
docker compose exec api python -m app.admin check-bot
```

Команда только вызывает getMe/getWebhookInfo и не меняет настройки Telegram. Она не может обнаружить внешний polling-обработчик. Если бот обслуживается другим приложением, не запускайте наш worker: существующее приложение нужно доработать или отдельно остановить по вашему решению. Существующий webhook автоматически НЕ удаляется.

### Вариант A: только Mini App, существующий обработчик остаётся

В BotFather выберите своего бота → Bot Settings → Menu Button (или /setmenubutton) и укажите https://bot.sotaholder.ru:8443, текст «Планировщик». Это изменение выполняйте осознанно: оно заменяет прежнюю кнопку меню. Откройте приложение через кнопку внутри Telegram. Вход проверяется сервером по initData и разрешён только OWNER_TELEGRAM_ID.

Работоспособность открытия Mini App с этим портом проверяется на ваших Telegram-клиентах. Публичный браузерный HTTPS на 8443 предусмотрен; если конкретный клиент ограничивает открытие, понадобится отдельный IP/сервер для стандартного 443 или отдельный согласованный прокси, а не отключение VPN.

Без нашего worker /today и /login существующего бота сами не появятся — их надо интегрировать в текущий код. Для входа в обычном браузере есть административный одноразовый код:

```bash
docker compose exec api python -m app.admin login-code
```

Код действует 5 минут и используется один раз. Вставьте его на странице входа. Не отправляйте его другим.

### Вариант B: наш обработчик для бота без другого работающего кода

Только если точно нет другого polling/webhook-обработчика:

```bash
docker compose --profile bot up -d bot
docker compose logs --tail=60 bot
```

Worker проверяет webhook и отказывается стартовать, если он есть; при Telegram 409 завершает работу, не останавливая сторонний код. Автоматический перезапуск worker отключён, чтобы не создавать бесконечный конфликт. После перезагрузки сервера worker нужно запустить явно той же командой. Веб-часть и БД перезапускаются автоматически.

В личном чате владельца:
- /start — кнопка открытия Mini App.
- /today — план на сегодня и кнопки выполнения (до 80 дел; остальные в приложении).
- /login — одноразовый код для обычного браузера.

Worker не сбрасывает команды и кнопку меню бота, не удаляет webhook и не очищает очередь обновлений. Старые обновления могут быть обработаны при первом запуске, если очередь не пуста. Не запускайте одновременно другого обработчика.

## 5. Перенос данных

Следуйте MIGRATION.md. Данные из локального файла не переносятся автоматически на другой origin. В новом приложении «Импорт JSON» заменяет серверные записи после подтверждения. Перед этим скачивается JSON прежней версии. При ошибке валидации интерфейс блокирует изменения до экспорта/загрузки корректной серверной копии.

## Сохранение и синхронизация

- Основное хранилище — PostgreSQL, один JSONB-документ пользователя для совместимости с прототипом. Это не нормализованная схема задач; на первой личной версии она упрощает перенос всех функций.
- API проверяет структуру, сроки и подпись входа Telegram. Доступ ограничен одним OWNER_TELEGRAM_ID.
- Токены сессии случайные, в БД хранится хеш; срок 7 дней. Браузер хранит токен в sessionStorage, не в URL. Коды входа одноразовые, 5 минут. Это чувствительные данные; не давайте другим доступ к DevTools.
- Есть revision-проверка: старая вкладка не может незаметно перезаписать новое состояние. При конфликте экспортируйте свои изменения и нажмите «Обновить с сервера». Автоматического объединения конфликтов нет.
- При сетевой ошибке черновик остаётся в памяти и по возможности в localStorage браузера. Статус сохранения виден сверху. Восстановление при следующем входе предлагает выгрузку черновика в JSON, а не автоматическую замену сервера.
- Веб проверяет обновления от бота/других устройств раз в 15 секунд, когда нет несохранённых изменений, активного поля ввода или открытого диалога. Это не WebSocket и не полноценный офлайн-режим.
- Прошлые метрики пересчитываются по текущим данным. Фиксации фактического времени и исторических итогов пока нет.
- API ограничивает импорт примерно 1,9 МБ, 500 дел и 50000 отметок. Последние 50 ревизий сохраняются в snapshots для диагностики/восстановления администратором, но это не замена внешним резервным копиям.

## Резервные копии

```bash
cd /opt/sotaplanner
sh scripts/backup.sh
```

Создаётся приватный PostgreSQL dump в backups/. Копируйте его на другое устройство. .env храните отдельно в защищённом месте. Том сертификатов Caddy содержит приватные ключи; его тоже можно резервировать отдельно. Регулярное расписание backup автоматически не устанавливается: настройте его после первой успешной ручной копии и проверки восстановления на тестовой БД.

Восстановление заменяет содержимое БД и прерывает только этот проект:

```bash
sh scripts/restore.sh backups/НУЖНЫЙ_ФАЙЛ.dump
```

Требуется подтверждение RESTORE. При ошибке сервисы могут остаться остановленными: не удаляйте тома, изучите вывод. После восстановления старые сессии отзываются; войдите заново. Worker запускается отдельно при необходимости. Не восстанавливайте непроверенный dump в рабочую БД.

## Обновление и остановка

Перед заменой файлов:

```bash
sh scripts/backup.sh
docker compose build api
docker compose up -d api web
```

Если используете worker, после обновления отдельно пересоберите/пересоздайте его:

```bash
docker compose --profile bot up -d --build bot
```

Остановить только приложение: docker compose stop web api bot. Данные сохранятся. НЕ запускайте docker system prune, docker network prune, docker volume prune и НЕ используйте docker compose down -v для обычного обновления.

Отозвать все сессии и коды:

```bash
docker compose exec api python -m app.admin revoke-sessions
```

## Проверки и ограничения поставки

Проверены компиляция Python, unit-тесты подписи Telegram и проверки данных, синтаксис JS, разбор Compose YAML и shell-скриптов. Дополнительно выполнен JS smoke-тест с имитацией DOM/API; он не заменяет настоящий браузер. Полный Docker-стек, выпуск реального сертификата, PostgreSQL-интеграция и обмен с реальным ботом в среде подготовки НЕ запускались. Это подготовленный к развёртыванию MVP, не обещание уже выполненного запуска и не аудит безопасности. После установки пройдите приёмку: вход, импорт, обновление страницы, изменение из бота, конфликт двух вкладок, backup, проверка VPN.
